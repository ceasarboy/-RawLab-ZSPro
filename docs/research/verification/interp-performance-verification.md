# 验证④ 记录：四面体 vs 三线性插值的性能预算与正确性

日期：2026-10-03。基准：`TetraBench.java`（同目录，JDK 17 编译运行，CPU 代理）。环境：Windows x64。

## CPU 基准结果（33³ LUT，4M 像素，7 轮取最优）

| 指标 | trilinear | tetrahedral |
|---|---|---|
| 吞吐 | 847 MP/s（1.2 ns/px） | 693 MP/s（1.4 ns/px） |
| 相对成本 | 1.00× | **1.22×** |

正确性交叉验证（先于基准执行，抓出并修正了两处实现错误）：

1. **恒等 LUT 还原误差**：修正后两种插值均为 **0.0**（任意点精确还原输入）。
2. **双方法最大偏差**（风格 LUT，200k 随机点）：0.0022 ≈ 1/512——即 33³ 晶格上两种插值的固有误差量级差，与文献中"四面体消除三线性的灰轴稀释伪影"的量级一致。
3. 开发过程中的两个教训（对 C++/GLES 实现同样适用）：
   - 四面体的顶点差必须**全部相对基准角点**（barycentric 展开 `c0 + w1(c1-c0) + w2(c2-c0) + w3(c3-c0)`），写成链式差分会在排序分支的共享面上产生不连续（实测恒等误差恰为一个格点步长 1/32）；
   - 六个排序分支中两个（g≥r≥b 与 g≥b≥r）的顶点路径易写错，**恒等 LUT 精确性测试是必须的单元测试**，进 CI。

## GPU 端预算分析（待真机确认）

| 项 | trilinear | tetrahedral | 备注 |
|---|---|---|---|
| 3D 纹理采样/像素 | 8 | **4** | 移动 GPU 常为采样/带宽受限，33³ fp16 LUT ≈ 430KB 可驻留 cache |
| ALU | 7 lerp/通道 | 2 次排序比较 + 3 差值 + 3 乘加/通道 | 差异以几十条指令计 |
| 预期 | 基线 | **相当或更快（采样受限时）** | 需真机确认 |
| 画质 | 饱和区向灰轴稀释，色相偏移可测 | 色相/饱和度保持显著更好 | Resolve 官方：tetrahedral "reduced color-banding"；OCIO `INTERP_BEST`=tetrahedral |

**结论**：CPU 代理下四面体仅贵 22%，GPU 端采样减半有望抵消 ALU 增量；画质收益（消色相偏移、减 banding）是四家专业软件的一致选择。**预算判定：直接实现 tetrahedral，不设回退路径的性能顾虑**；真机数字见下方待办。
